---
title: "Backend architecture"
description: "Follow a document through the Go runtime, find the owning code, and verify changes without breaking storage or security boundaries."
---

Suchi turns incoming files into a local archive: capture, extract, file,
retrieve, and review. Each step must remain useful without an LLM or an external
service. The production distribution is one statically linked Go binary with
an embedded Svelte application, SQLite, immutable blobs, and rebuildable filing
views under `DATA_DIR`. It needs no database server, cache, or message broker.

This guide describes the implementation in this checkout. Product proposals in
`../specs/` can include future work or contracts implemented on other branches;
check the source and contract tests before carrying them into a change. For
browser composition and bundle ownership, see [Frontend architecture](/spa-architecture).

## Where to start a change

These are ownership boundaries, not interchangeable layers or a directory inventory.

| Concern | Entry point and owner |
| --- | --- |
| Process lifecycle and dependency wiring | `distro/cmd/suchi/main.go: runServe`; `serve_*.go` assembles runtime services and HTTP policy |
| JSON requests and wire contracts | `core/api/api.go: Server.Register`; feature handlers stay together in `core/api/` |
| Browser entry pages and blob delivery | `core/ui/ui.go` and `core/ui/spa.go`; API preview/download mirrors are wired in the CLI |
| Identity and access decisions | `core/auth/`, `core/authz/`, `core/httpx/`; credential implementations in `plugins/local-auth/` and `plugins/oidc/` |
| Durable state and work | `core/db/db.go`, `core/db/migrations/`, `core/blob/cas.go`, `core/jobs/jobs.go` |
| Capture and processing | `core/api/documents.go: UploadDocument`, `core/ingest/`, `core/importer/bundle/`, `core/pipeline/postingest/` |
| Filing, review, and retrieval | `core/jd/`, `core/automations/`, `core/approvals/`, `core/searchquery/`, `core/intelligence/`; their HTTP projections live in `core/api/` |

Keep behavior in its existing domain owner. `plugin-api/` is the small shared
vocabulary for authenticators, job subscribers, and audit sinks, not a service
framework. Plugins are compile-linked; there is no runtime Go plugin loader.
The API receives explicit callbacks from the CLI when it needs an integration
without importing `plugins/*`.

## Boot and shutdown

Follow `runServe` when a service works in a unit test but is absent at runtime:

1. Load and validate configuration, create `DATA_DIR`, open SQLite, apply
   embedded migrations, and establish the Johnny.Decimal Inbox invariants.
2. Construct authentication, CAS, rendering, retention, encryption keys, and
   configured integrations. Optional parser availability is reported without
   making a missing tool a startup failure.
3. Register all durable subscribers before reclaiming interrupted jobs and
   starting the dispatcher. Start the configured intake supervisors, backup,
   and retention loops.
4. Construct the API and browser handlers, inject runtime dependencies, register
   routes, then wrap the assembled mux in the HTTP middleware.
5. On termination, cancel the shared context and shut down HTTP with a bounded
   grace period. Subscribers and subprocesses must honor cancellation.

This is a single-server-process design. The single writer and startup job
reclamation are not coordination for multiple servers sharing one database.

The executable resolves its build version and source revision once at boot and
passes them to the API. Authenticated `/api/whoami` responses expose
`build_version` and optional `build_revision`; Settings displays that existing
session metadata. Docker builds receive the revision explicitly because their
context excludes `.git`. This is build identification, not an update service.

## From upload to usable document

```mermaid
flowchart LR
  I[Upload or intake] --> B[Original bytes in CAS]
  B --> T[Commit document, source, and first job]
  T --> J[Durable dispatcher]
  J --> P[Extract and normalize]
  P --> F[File and review]
  P --> S[(SQLite text and metadata)]
  P --> D[Derived CAS objects]
  F --> S
  S --> A[ACL-filtered retrieval]
  D --> A
  A --> C[Web app and API clients]
```

For a new upload, `UploadDocument` follows this sequence:

1. Require write scope and enforce the HTTP body limit. Sniff the content;
   the supplied MIME type is not authoritative.
2. Stream the original into CAS before opening the database write transaction.
3. In one transaction, resolve owner/hash deduplication or insert the document,
   record acquisition provenance, and enqueue `post-ingest` for a new document.
4. After commit, nudge the dispatcher and emit the audit event. A lost nudge
   cannot lose the persisted job. Re-uploading an existing live document records
   its source without adding another extraction job.
5. The post-ingest subscriber selects the format path, extracts content, and
   writes derived bytes and metadata. Its common post-content path performs
   local archive matching, automations, filing-view and thumbnail refresh, and
   the optional `post-classify` handoff.

Mail attachment creation and post-ingest refine missing, generic, or malformed
MIME labels from the original bytes through `core/mimeutil`. Specific valid
source types remain intact. An explicit rescan can therefore repair a PDF
previously labeled `bin` and reach the ordinary encrypted-PDF gate; it does not
modify the original CAS object or require a pipeline revision change.

Filesystem and IMAP intake have their own producer code and use the same
transactional document/job pattern. Import is deliberately different:
`core/importer/bundle/` can restore supplied content, archive bytes, and
metadata without automatically scheduling fresh extraction. Do not assume
every document row means a new processing job.

`document_sources` describes acquisition, not document identity. The same owner
and original hash can have several sources; one CAS object can be referenced by
different documents. Mailbox history retains its observed name/folder even if
the configured account is deleted. Split children and email attachments inherit
sources; a version records its own upload. Sources, version chains, and document
relationships are not substitutes for one another.

## Storage and transaction invariants

`DB.Write` has one connection; `DB.Read` has a small concurrent pool. Both open
the same SQLite file with WAL, foreign keys, a busy timeout, and bounded memory
mapping. Use `WriteTx` for mutations and pass its `*sql.Tx` into helpers that
participate in that transaction. Re-entering the write pool from inside a
transaction waits on the connection already held by the caller.

Keep network calls, subprocesses, and long file processing outside write
transactions. Enqueue required asynchronous work with the state change that
requires it, not in a separate best-effort write afterward. Audit logging is
generally post-commit and must not be mistaken for a transactional job outbox.

Original and derived bytes are addressed by SHA-256:

```text
$DATA_DIR/blobs/sha256/ab/cd/ef/<full-hash>
```

`CAS.Put` hashes a stream into a temporary file at the CAS root, then renames it
into its shard on the same filesystem. SQLite and the filesystem are not one
transaction: a later database failure can leave an unreferenced blob. Online
purge, including demo visitor expiry, never deletes CAS bytes: it cannot
distinguish an unused hash from an in-flight publisher reusing it. Only offline
GC reclaims blobs, with the server
and all other archive writers stopped. A blob's age is not a concurrency guard.
Do not delete by hash on a request failure; another document may reference it.

Preserve `original_blob` and the original MIME type. Decryption, normalization,
and OCR create derived objects rather than overwriting the upload. The rendered
Johnny.Decimal tree is a rebuildable projection. Trash and retention remove
document state and rendered files; `core/gc/` owns physical CAS reclamation.
Back up the complete data directory with writers stopped or an atomic whole-
directory snapshot, including the keys that decrypt sealed credentials. A
database-only snapshot is not a complete archive backup.

Migrations are embedded and ordered. Fold unreleased schema changes into the
current release migration; never rewrite a migration already published in a
release. Features targeting a later release use the next migration after the
prepared release. Startup validates every version before touching the database
and rejects duplicate or nonpositive versions with the conflicting names.
See [Release process](/release-process).

## HTTP and security boundaries

`distro/cmd/suchi/serve_middleware.go: buildHTTPHandler` composes request IDs,
security headers, access logging, metrics, body limits, authentication, token
policy, and Fetch Metadata checks around the normalized API mux.

These gates answer different questions:

- **Authentication:** `core/auth` establishes a principal. OIDC is checked
  before local authentication and delegates Suchi's exact API-token shape to
  it; anonymous demo authentication is last. Invalid credentials cannot fall
  back to a browser session. Both OIDC login paths require signed verified-email
  claims before binding a local account. The configured issuer remains trusted
  to control email assignment; email is not a stable subject identifier.
- **Token authority:** `serve_token_policy.go` explicitly lists routes available
  to local API tokens and restricted demo scratch identities. Unlisted routes are session-only;
  an admin role does not bypass this boundary. Add a route's scope deliberately
  and test the assembled handler, not only the bare API method.
- **Roles and capabilities:** handlers enforce administration or feature grants,
  including archive chat and intelligence. Scopes do not imply those grants.
- **Object authorization:** `core/authz` combines ownership, administrator
  access, direct grants, and group grants. Lists, counts, search, and similarity
  constrain visibility in SQL before pagination, not by filtering returned rows.
- **Browser origin:** cookie-session mutations reject sibling-origin
  `same-site` and `cross-site` Fetch Metadata requests. Same-origin and
  headerless compatibility requests remain supported; explicit token/bearer
  integrations are exempt. Do not replace this with a CORS-only check.

The public token scopes are `documents:read`, `documents:write`, and
`events:read`; they are distinct grants, not a hierarchy. A feed-only token
cannot read document content. Document-read access still needs a document ACL.
Token management requires a browser/OIDC identity: API tokens cannot mint,
list, or revoke credentials. Admin-token metrics remain a deliberate exception;
read [HTTP API](/api) before changing compatibility.

Browser demo visitors use HttpOnly cookies too. The anonymous cookie is signed
and stateless; the first write exchanges it for an ordinary digest-backed
session bounded by the scratch TTL. Local authentication recognizes the reserved
scratch user and retains its restricted scopes on API, preview, and download
requests; it must never become an unrestricted member session. The CLI injects
local session issuance into the demo provisioner, without a separate credential
store or schema. See [Demo instance](/demo-instance) for retention and isolation.

Preview/download aliases share `core/ui`'s blob-serving behavior, including
object checks, reveal gates, ETags, and preview CSP. These endpoints allow
trashed documents only for their owner or an administrator, matching the Trash
scope; ordinary ACL readers and public share links cannot fetch trashed bytes.
Thumbnails have their own live-document handler in `core/api/documents_thumb.go`.
High sensitivity is a reveal posture,
not an additional tenant boundary. Normal API document reads can return content
to an authorized reader; untouched `raw=1` downloads are an administrator
session-only surface.

Mailbox secrets, OAuth caches, PDF passwords, and model keys are sealed.
Browser session identifiers and API tokens are stored as digests. Audit events
must exclude document bodies and credentials, including share bearers. Access
logs and metrics use matched route patterns; request copies must propagate that
pattern back to the outer middleware. See [Permissions](/permissions)
and [Privacy](/privacy) for the user-facing contract.

## Retrieval, filing, and human review

`core/searchquery` parses a bounded flat clause list, resolves symbolic names
at the API boundary, and compiles parameterized SQL and FTS constraints.
`core/api/search_query.go` connects that plan to both ranked Search and sortable
Documents. Keep the document set consistent while retaining each endpoint's
different response shape. Saved views use the same query contract.

Local archive matching fills unresolved metadata before user automations.
Automations are the deterministic trigger/condition/action engine; approvals
are the state-machine engine for human decisions. Do not introduce a second
workflow engine for a new intake source or integration.

`core/intelligence` validates reviewable extracted facts; its API applies
source-document visibility and fact filters before counts and pagination.
Calendar's exact-day requests use the date `precision` filter so month/year
sorting placeholders cannot become day events; see [Document dates](/document-dates)
and the [API reference](/api#extracted-facts-archive_intelligence).
Archive chat is bounded, on-demand retrieval in
`core/api/chat.go`, not a background job or a general agent runtime. It uses
the same configured model integration through explicit callbacks. Preserve
evidence limits, review decisions, and human-edited metadata when changing
extraction or classification.

## Durable work and optional integrations

`core/jobs/jobs.go` owns claims, retries, and dead letters. Current job kinds
are `post-ingest`, `post-classify`, `render`, `approval:advance`, and
`approval:timeout-sweep`. The dispatcher drains ready work in serial batches;
polling is only the idle fallback. A job can run again after failure or a
crash, including when its side effect succeeded but completion was not recorded.

Subscribers must be idempotent, honor cancellation, and keep payload contracts
beside their owner. Register before `Run`; the registry is not dynamically
synchronized. Unknown kinds and terminal errors become `dead`; other failures
retry with bounded attempts/backoff. Pipeline versions in the processing
owners let rescan target stale results.

Local parsing remains useful without the optional classifier. Remote model
endpoints require explicit egress acknowledgement, and redirects are rejected.
Intake and identity integrations have their own configured destinations; do not
make useful local operation depend on a Suchi-operated service.

The MCP adapter calls the configured Suchi origin without following redirects.
It accepts bounded valid JSON and keeps query values, response bodies and
transport diagnostics out of tool errors. Its tool contracts remain ordinary
scoped API requests; it does not bypass HTTP or object authorization.

External parsers run through `core/sandbox` with timeouts, bounded captured
stdout/stderr, explicit environment, and temporary working directories.
Unix cancellation kills the process group. This is a subprocess resource
wrapper, **not OS-level isolation**: it does not deny filesystem/network access
or impose process memory limits. Keep format-specific input/output limits and
deployment isolation explicit; a unit test with a stub executable does not
establish the safety or availability of the real parser.

`core/pipeline/imgpdf/` owns all supported raster-to-PDF conversion, including
HEIC/HEIF; there is no separate HEIC adapter or intermediate PNG step. It
explicitly requests PDF encoding and rejects output without the PDF signature
before OCR/CAS publication. Camera EXIF orientation is applied to derived pixels,
and PDFs use 300-DPI page density without resampling, matching the OCR rasterizer
instead of inflating phone photos into oversized pages. ImageMagick scratch stays
inside the converter's temporary directory and is removed after conversion.
Container ImageMagick policy permits the necessary
PDF writes without enabling PDF reads. Verify the actual encoder and policy,
not merely an executable's presence or an `archive_blob` value. See
[Supported file types](/formats) and [Pipeline versions](/pipeline-versions)
for frame handling, dependencies and repair of older image archives.

## Change and verification map

Start with the affected boundary, then run the aggregate loop.

| Change | Focused verification |
| --- | --- |
| Routes, scopes, credentials, or ACLs | `go test ./core/auth/... ./core/authz/... ./core/httpx/... ./core/api/... ./core/ui/... ./distro/cmd/suchi/...`; cover denied principals, aliases, counts, and direct blob routes |
| Query/filter semantics | `go test ./core/searchquery/... ./core/api/...`; preserve Search/Documents parity and hidden-document exclusion |
| Ingest or a format tool | `go test ./core/ingest/... ./core/pipeline/... ./core/sandbox/...`; verify original preservation, retries, and the affected real-tool smoke test |
| Queue or concurrent runtime state | `go test -race ./core/jobs/... ./distro/cmd/suchi/...`; exercise backlog draining, cancellation, and restart recovery |
| Schema, blobs, or deletion | `go test ./core/db/... ./core/blob/... ./core/trash/... ./core/gc/... ./core/importer/bundle/...`; cover migration and shared-blob references |
| Filing, model suggestions, or review | `go test ./core/automations/... ./core/approvals/... ./core/intelligence/... ./plugins/llm-classifier/...`; preserve human decisions and no-model behavior |

```sh
make check        # format, vet, tests, staticcheck across Go modules; UI and embedded parity
make smoke        # build; health/readiness against a disposable loopback server
make docs-check   # documentation links
```

Use a writable `GOCACHE` in a restricted environment. To force re-execution, use
`make test TEST_FLAGS='-count=1 -timeout 60s'`. The race detector needs a working
CGO toolchain. UI changes additionally require `make ui` and
the relevant browser regressions. Use focused benchmarks for a claimed local
performance win and `make bench-check` for startup/memory/binary guardrails.

When a change moves ownership, entry points, state flow, or an invariant, update
this guide in the same change. Update the relevant public API/feature guide and
changelog for observable changes. Report missing real-tool or runtime checks
explicitly; passing mocks does not establish end-to-end compatibility.
