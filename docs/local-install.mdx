---
title: "On your computer"
description: "Install a private archive on Linux or macOS without Docker, a domain, or hosting."
---

Open Suchi like an application, use it in your usual browser, and keep your
documents on your computer. It is the same archive format and application as
the server edition. No account with a Suchi service is required.

These installers are **unreleased evaluation builds**, not included in beta.2.
Linux has native service and ingestion checks; the macOS desktop flow still
needs acceptance testing on a real Mac. macOS evaluation bundles are not
Developer ID-signed or notarized. Do not disable Gatekeeper, clear quarantine,
or change system security policy to run them. Windows installation is deferred.

## Get the right download

Local bundles are named `suchi-VERSION-local-OS-ARCH.tar.gz`. Choose `linux`
for Linux or `darwin` for macOS, and `arm64` for Apple Silicon/ARM or `amd64`
for Intel/AMD. They contain Suchi, its installer, and launchers—not document
tools or a bundled model. You do not need Go or Docker to use a bundle.

Verify its SHA-256 file against the trusted download source, then extract the
whole archive. A checksum detects damage; it does not replace publisher
verification or macOS code signing.

## Install on Linux

Use a graphical Linux session with systemd's user manager. Open `Install.sh`
from the extracted folder (or run `bash ./Install.sh` there). **Check your
computer** shows each required tool and whether it is ready, missing, or needs
attention. Installed tools can still need attention—for example, missing
English OCR data or an image converter blocked from creating PDFs. Follow the
manual package guidance, then choose **Check again**. Continue when the checks
pass; choose whether Suchi should start at login, install, then **Open Suchi**.
Login startup is off by default on a new installation.

Suchi guides you through missing tools; it never installs system packages for
you. For Debian/Ubuntu, the prerequisite command is:

```sh
sudo apt install zenity xdg-utils qpdf poppler-utils tesseract-ocr tesseract-ocr-eng imagemagick
```

The installer also provides Fedora and Arch package guidance. It checks English
OCR data and tries image-to-PDF conversion, not just executable names. Some
distributions disallow ImageMagick PDF writes; installation reports that policy
instead of changing it. Review your distribution's policy before proceeding.

Run the Suchi installer as your desktop user, **without sudo**. Only your
package manager needs elevated privileges. The service finds document tools
in `/usr/local/bin:/usr/bin:/bin`.

## Install on macOS

Open `Install.command` from the extracted folder. **Check your computer** shows
ready tools and anything missing or needing attention, even if every check
passes. It offers **Check again** after you install missing prerequisites.
If you already use [Homebrew](https://brew.sh), run:

```sh
brew install qpdf poppler tesseract imagemagick
```

The installer never runs this command or installs Homebrew automatically.
Homebrew's [Tesseract package](https://formulae.brew.sh/formula/tesseract)
includes English OCR data; additional languages need `tesseract-lang`.
The service searches standard Apple Silicon and Intel Homebrew locations.

Choose **Only when opened** or **Start at login**. Installation adds **Suchi**
and **Suchi Settings** to your user Applications folder. Choose **Open Suchi**
when installation finishes. Suchi uses a per-user LaunchAgent, not a privileged
system daemon. Reopening the application reuses the running archive.

## First launch

A native dialog shows your one-time setup token. Copy it, choose **Open Suchi**,
then paste it into the browser form and create your administrator email and
password. Suchi then offers its filing-tree and archive setup.

The token is never put into a browser URL or automatically copied to the
clipboard. It is removed after setup and is not your login password. If it
expires, retrying setup replaces it; open Suchi again to see the new token.
Cancelling the dialog leaves the browser closed.

The service binds only to `127.0.0.1`. No hosts-file changes, reverse proxy,
domain, or firewall exception is needed. The launcher verifies that Suchi has
started before opening the browser; a different application using the port
does not count as a successful start. Normal authentication remains required.

## Everyday controls

On Linux, right-click Suchi's application shortcut for **Settings** or **Stop**.
If your desktop does not expose shortcut actions, run the installed
`program/launch.sh --settings`. On macOS, open **Suchi Settings**.

Local settings let you open the archive, change startup at login, stop Suchi,
or uninstall. Document preferences remain in the browser's Settings.
Closing a browser tab does not stop intake or processing. Stopping Suchi pauses
them until you open it again or it starts at your next login.

While the computer sleeps or is shut down, it cannot process documents or poll
mail. The next start resumes persisted work and mailbox polling. The Linux
installer does not enable systemd lingering after logout.

## Storage, updates, and uninstall

| Purpose | Linux default | macOS |
| --- | --- | --- |
| Archive, database, keys | `~/.local/share/suchi-local/archive/` | `~/Library/Application Support/Suchi/archive/` |
| Program and launchers | `~/.local/share/suchi-local/program/` | `~/Library/Application Support/Suchi/program/` |
| Configuration | `~/.config/suchi-local/local-install.toml` | `~/Library/Application Support/Suchi/config/local-install.toml` |

These directories are private to your OS user. Linux honors `XDG_DATA_HOME`
and `XDG_CONFIG_HOME`; keep the same values for install, update, and uninstall.
Neither installer adopts a development or server database. Paths with spaces
work; paths with unsupported escaping characters are rejected explicitly.

Before updating, stop Suchi and back up the **entire archive directory plus its
configuration**. Keep it stopped while copying. Then run the new installer.
Updates preserve documents, keys, configuration, port, and login preference
unless you explicitly change an option. A running service is stopped before
its executable is replaced. There is no background updater or automatic
rollback across database migrations.

**Uninstall Suchi** asks for confirmation, stops the application, and removes
its managed program, launchers, and service. It **keeps your archive and
configuration**, including keys. Reinstalling reopens them. Deleting the app
icon alone is not the uninstall procedure.

Local storage is not a backup. Database snapshots alone do not contain your
documents and keys; follow [Backup and restore](/backup-restore). Keep the live
archive out of Dropbox, OneDrive, iCloud Drive, and similar file-sync folders.

## Limits and troubleshooting

- Share links and **Open on my phone** use this installation's URL. Loopback
  links cannot be reached from another device. The installer does not expose
  Suchi to the LAN or create a tunnel.
- Models, email, and other integrations remain opt-in. The service does not
  inherit their credentials from your shell.
- The required tools cover PDFs, scanned PDFs, common images, text, and email.
  Office/EPUB extraction needs AnyDoc; see [Supported file types](/formats) for
  optional helpers and codec limits.
- Parsers run as your OS user. Timeouts and output limits are **not OS-level
  isolation** from your other files. This is not a sandbox for hostile documents.

Startup errors appear in a dialog. Linux logs are available with
`journalctl --user -u suchi-local.service`; macOS logs are in
`~/Library/Application Support/Suchi/runtime/server.log`.

To select another unused port, run the extracted installer's command-line path:

```sh
./install.sh ./suchi --port 8001
```

Developers can build from this checkout with `make build`, then use
`deploy/local-linux/install.sh ./dist/suchi` or
`deploy/local-macos/install.sh ./dist/suchi`. The platform READMEs describe
verification and the remaining native acceptance checks.
