The self-hosted document-management space has mature alternatives. This page
focuses on operational shape and documented features, not a universal ranking.

**Snapshot date:** 2026-10-20. Read each project's current documentation before
choosing; all four projects are active, though Docspell's last release was
v0.43.0 in March 2025.

<Warning>
  This comparison is maintained by the suchi project. It is not an independent
  review, and only suchi's performance numbers were measured here.
</Warning>

## At a glance

| Project           | Default operational shape                                                                                              | License  |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- | -------- |
| **suchi**         | One Go server process, SQLite, filesystem CAS; converters and the Android/iOS Companion app are optional              | AGPL-3.0 |
| **Paperless-ngx** | Web, consumer, task worker, and scheduler processes; SQLite by default (PostgreSQL or MariaDB optional) plus a required Redis-compatible broker | GPL-3.0  |
| **Papra**         | Packaged Node application with SQLite and filesystem storage by default                                                | AGPL-3.0 |
| **Docspell**      | Separate REST and joex processes; embedded H2 by default (PostgreSQL recommended); full-text search is optional        | AGPL-3.0 |

Sources: [Paperless-ngx configuration](https://docs.paperless-ngx.com/configuration/),
[Papra configuration](https://docs.papra.app/self-hosting/configuration/), and
[Docspell prerequisites](https://docspell.org/docs/install/prereq/).

The watched-folder row is a real workflow difference. Paperless-ngx and Papra
treat the drop folder as a temporary inbox and empty it by default. Suchi never
moves, renames or deletes files there, and its organised tree is a separate
folder of links that Suchi keeps current. Docspell's CLI watcher also leaves
files in place unless told to delete or move them.

## Resource profile

The accepted v0.1 suchi benchmark measures a 25.5 MB stripped binary, 31.9 MB median
idle RSS, 86 ms cold start to `/healthz`, and 625 accepted upload requests/s in
the 10-user x 20-document scenario. Upload acceptance is measured separately
from asynchronous extraction. See
[`hack/bench/`](https://github.com/johnnybravo-xyz/suchi/tree/main/hack/bench)
for the harness and machine details.

This project has not run equivalent controlled benchmarks for the alternatives,
so it does not publish comparative RAM, image-size, startup, or throughput
figures. Container size and idle memory are not interchangeable with total
operational cost.

## Choosing deliberately

### Paperless-ngx

Choose Paperless-ngx when ecosystem maturity, community mobile clients,
extensive documentation, PDF editing, and a broad workflow surface matter more
than minimizing process count. Its 3.x releases added document version history,
optional AI suggestions, chat and auto-apply workflows, and a new search
backend. SQLite is the default; PostgreSQL is recommended for new or multi-user
installations. A Redis-compatible broker is required.

### Papra

Choose Papra for a focused responsive web UI, organizations, SQLite-first
deployment, folder and email-relay ingestion, configurable extraction backends,
built-in LLM auto-tagging, typed custom properties, advanced search, and
expiring or password-protected share links. An Android app is released as an
APK on GitHub. Papra's README lagged its changelog at this snapshot, so the
shipped changelog takes precedence here.

### Docspell

Choose Docspell for multi-file items, strong query capabilities, scalable REST
and joex processes, IMAP and SMTP-gateway intake, an Android upload client, and
optional Solr or PostgreSQL full-text search. Its embedded H2 setup avoids an
external database, but fine-grained permissions and document versioning are
documented limitations. Releases are infrequent: v0.43.0 shipped in March 2025,
and later work is on the main branch.

### suchi

Choose suchi when one server process, a filesystem CAS, low measured idle
memory, filing trees based on the Johnny.Decimal concept, multi-party
correspondents, approval tasks, an audit feed, MCP tools, and a first-party
Android/iOS app fit the problem. Companion pairs by QR code and provides
capture, foreground uploads, Inbox filing, browsing, search, privacy-gated
previews, offline saves, sharing, and Trash recovery. Choose it too when you
want a folder tree you can browse without Suchi, a drop folder that is never
emptied, or version history and named document links. Do not choose suchi for
ecosystem maturity or proven compatibility with Paperless mobile clients; it is
a younger project than the alternatives.

## Portability

- **Paperless-ngx to suchi:** `suchi import --from <dir>` consumes a compatible
  Paperless export bundle.
- **suchi takeout:** `suchi export --out FILE.zip --system S02 --all` writes a
  partial manifest-v3 export of that one system's originals, sidecars and
  taxonomy for every owner there. Archive serial numbers are preserved when
  reingested into a system where the value remains available. Without
  `--system`, the original system is selected; without an owner flag, owner
  inference must be unambiguous. Reingestion can allocate new IDs and does not
  restore membership or ACLs.
- **suchi backup:** preserve the whole SQLite/CAS/key set for an exact restore
  of systems, memberships, IDs and relationships; see [Backup and restore](/backup-restore).
- **suchi to another DMS:** there is no destination-specific exporter. The
  takeout is documented and uses ordinary files plus JSON sidecars, but mapping
  it into another product remains migration work.
