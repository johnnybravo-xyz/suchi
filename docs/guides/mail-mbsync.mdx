---
title: "Mail intake with mbsync"
description: "Mirror IMAP into Maildir and hand EML files to Suchi's watched folder."
---

The `deploy/mail-mbsync/` Compose recipe runs mbsync beside Suchi. mbsync
mirrors selected folders into Maildir and fans new messages into Suchi's
watched directory. Suchi then ingests EML and attachment documents through its
normal pipeline.

Prefer the built-in [Mail intake](/guides/mail-intake) poller unless you need a
local Maildir mirror, already operate mbsync, or want mailbox credentials kept
outside Suchi.

## Configure and start

```sh
cd deploy/mail-mbsync
./setup.sh
docker compose up -d
docker compose logs -f mbsync suchi
```

`setup.sh` asks for provider, credentials, folders, limits, and local UID/GID.
It writes `config/.env` for container settings and `.env` for Compose settings.

For Proton, initialize the Bridge profile first and use the Bridge-generated
IMAP password:

```sh
docker compose --profile proton run --rm -it bridge init
```

## Persistent paths

| Path | Contents |
| --- | --- |
| `config/.env` | IMAP and Suchi settings; contains credentials |
| `.env` | Compose profile, port, and UID/GID |
| `maildir/` | mbsync state and local message mirror |
| `ingest/` | Temporary handoff to Suchi |
| `suchi-data/` | Database, blobs, keys, and snapshots |
| `bridge-data/` | Proton Bridge state when enabled |

Back up `config/.env`, `.env`, Maildir state when needed, and the complete
`suchi-data/` directory. Restrict credentials to the deployment user.

## Configuration changes

Re-run `./setup.sh` or edit `config/.env`, then reload the external mbsync
container:

```sh
docker compose restart mbsync
```

This is not a Suchi restart. Built-in mailbox settings use live supervisor
reload and do not need either command.

The reference Compose file does not mount the Docker socket. Avoid adding that
root-equivalent capability merely to automate a sidecar reload.

## Verification

`./smoke-test.sh` exercises the generic provider handoff, EML ingest, and
attachment fanout with synthetic data. It requires Docker and cleans up its
test containers.

Common issues:

- The first sync is bounded by `MAIL_MAX_MESSAGES`; later runs are incremental.
- `MAIL_MAX_SIZE` skips oversized messages.
- Proton labels appear as IMAP folders through Bridge.
- Gmail's All Mail overlaps Inbox; select explicit folders to avoid duplicate
  local copies.

Stop containers with `docker compose down`. Remove local directories only when
you intend to delete credentials, mirrored mail, and the Suchi archive.
