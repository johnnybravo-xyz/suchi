**Suchi** is a self-hosted document management system delivered as one Go
binary with SQLite, content-addressed storage, a Svelte interface, and an HTTP
API. Its name comes from Sanskrit _suchi_: an index, catalog, or list.

<Warning>
  Suchi v0.1.0 was the first stable-v1 database release; v0.3.0 is current. Back up and test
  restoration before using it for a critical archive, and pin production images
  by their published digest.
</Warning>

## Product shape

- **Small operational footprint.** No database server, cache, message broker,
  telemetry service, or remote UI assets. Reproducible measurements live with
  the benchmark harness rather than being treated as a cross-host guarantee.
- **Guided filing.** Archive Configuration compares built-in Johnny.Decimal
  filing trees and imports custom trees.
- **Independent filing systems.** A prefixed taxonomy import introduces permanent
  system codes and `SYS.AC.documentID` addresses. Direct membership admits a user
  to a filing system; document ACLs still control what they can open there.
- **Broad intake.** Uploads, watched folders, IMAP mailboxes, common office and
  image formats, text recognition (OCR), encrypted PDFs, and portable bundles
  use one reliable processing queue.
- **Search and workflow.** Full-text queries, saved document sets, automations,
  approval reviews, document-date Calendar, rescans, and rendered filesystem
  views are built in.
- **Optional model assistance.** Local or hosted OpenAI-compatible models can
  apply metadata and dates under the configured policy, leave other suggestions
  for review, and answer questions with links back to the documents used.
- **Controlled sharing and integration.** Shared users/groups and global roles,
  system-bound tokens, object ACLs, share links, OIDC, HTTP APIs and MCP retain
  the same membership and document-permission boundaries. SQLite/CAS, server
  administrators and host/backup access remain shared, not separate infrastructure.
- **Explicit egress.** Stock Suchi has no telemetry or cloud dependency.
  Configured mail, identity, and hosted LLM integrations are visible
  to the operator. Operator-provided pre-consume scripts are unrestricted
  processes and sit outside that inventory.
